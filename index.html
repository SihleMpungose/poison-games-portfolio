DEVELOPMENT JOURNEY

How the work changed me as a developer.

This section is about progression and lessons — not current game status.

01
FOUNDATION

Start with testing and logic

My IT background and QA practice taught me to break problems down, reproduce issues and think about software from the user’s side.

02
FIRST PLAYABLE BUILDS

Connect ideas into complete loops

Building games taught me that individual features matter less than whether the whole experience works from start to finish.

03
PUBLIC TESTING

Real players find different problems

Moving from my own testing into public builds changed how I think about regression, save safety, usability and clear release notes.

04
STORE RELEASES

Development does not end at “build succeeded”

Publishing introduced store requirements, packaging, testing tracks, version management, release timing and support after launch.

05
NOW

Learning to prioritise without stopping experimentation

My current stage is about supporting live work properly, pausing projects when necessary and using short game-jam projects as controlled experiments rather than turning every new idea into another long-term commitment.
